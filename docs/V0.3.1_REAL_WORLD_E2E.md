## MasterDnsVPN — confronting the real binary (§11, decisive)

The official MIT-licensed release (`MasterDnsVPN_Client_Windows_AMD64.zip`,
tag `v2026.06.13.234407-7de2476`) was downloaded to a temp dir (never
committed) and driven directly:

| Check | Result |
| --- | --- |
| `-version` | `MasterDnsVPN Client Version: v2026.06.13.234407-7de2476`, exit 0 |
| Config generated by Atlanhix (fixed schema) | **ACCEPTED** — `Client Configuration Loaded`, `Client Mode, Protocol: SOCKS5 Encryption: 1`, `Configured Domains: 1`, `Loaded Resolvers: 2 endpoints` |
| Resolvers sidecar | **REQUIRED** — client refuses to start without `client_resolvers.txt` (`resolver file not found`); now always generated + passed via `-resolvers` |

| Secret handling | `KEY-IN-CONFIG: false` — shared key only on argv (`-k`), redacted in all output |

### Bugs found & fixed (each with regression tests)

1. **Invented config schema** — v0.3.0 generated
   `SERVER_ADDRESS/SUBDOMAIN/SERVER_PUBLIC_KEY/SOCKS5_LISTEN_*` which the real
   client does not know. Real schema: `DOMAINS=[..]`, `DATA_ENCRYPTION_METHOD`
   (int), `PROTOCOL_TYPE="SOCKS5"`, `LISTEN_IP`, `LISTEN_PORT` (int), `MTU`.
2. **Wrong CLI flags** — v0.3.0 used `--config` (double-dash). Real client:
   `-config <path>` (Go flag style), plus `-resolvers`, `-k <key>`, `-log`,
   `-version`.
3. **Wrong binary name** — v0.3.0 searched `mdvpn-client`; upstream ships
   `masterdnsvpn-client` (legacy alias kept as fallback).
4. **Wrong version flag** — `--version` → `-version`; version regex now
   accepts date-based tags.
5. **Missing resolvers sidecar** — discovered by the real binary; `start()`
   now writes `client_resolvers.txt` (profile resolvers or `8.8.8.8`/`1.1.1.1`
   defaults) and passes `-resolvers`.

## Parallel test safety (§21) — fixed

Root cause: two test files grabbing the same *preferred* engine port when
`flutter test` runs files in parallel. Fix (two layers): every engine port is
dynamically allocated via `PortAllocator` (`prefer:` is only a hint) —
including a new **dynamic MDVPN SOCKS port per CoreManager** — and
`dart_test.yaml` now sets `concurrency: 1` so engine-bound suites serialize
by default. Full suite passes without manual flags.

## Security audit (§22)

* No secrets in the repository tree; **no secrets in git history**
  (`git log --all -S` for key/URL literals: clean).
* `u.hixyz.ir` appears only as a parser unit-test domain (task-provided
  server name, not a credential).
* MDVPN shared key: never written to config files; travels via `-k` argv;
  **moved out of plaintext persistence** — import moves it to `password`
  (vaultified at storage) and redacts `ENCRYPTION_KEY` from the stored raw
  TOML (`<redacted>`), with regression tests.
* Logs are redacted by the central `Logger.redact`; the binary-validation
  harness masks argv secrets before printing.
* Generated configs land in per-instance temp dirs and are cleaned on stop.
* No TLS verification was weakened anywhere; no test-only production
  behavior added; the supplied domain is never special-cased.
