# AmneziaWG 3.1 on Android — Feasibility Study & Build Recipe

**Scope:** v0.4.8 §user — replace the plain-WireGuard WARP hop with an
AmneziaWG-3.1-masked peer on **Android**, where the tunneling engine is the
bundled `libbox` AAR (`android/app/libs/libbox.aar`, built from upstream
sing-box **v1.14.0**).

**Conclusion up front:** **feasible, two viable paths, no core rewrite.**
The app already generates the correct sing-box config surface (endpoint
fields `jc/jmin/jmax/s1/s2/h1..h4` — wired in v0.4.8). The only missing
piece is a libbox binary that *executes* the AWG handshake. Two forks ship
that today; both are drop-in replacements for the AAR.

---

## 1. Why the stock AAR cannot do it (measured, not guessed)

The bundled `libbox.aar` is upstream sing-box v1.14.0. Evidence:

* `grep -a "junk" libgojni.so` in the AAR → **zero hits**; no
  `amnezia`/`jc`/`jmin` strings either (checked 2026-09, this repo).
* Upstream has an OPEN feature request for AWG
  (SagerNet/sing-box#4045 — "AmneziaWG 2.0", Apr 2026; earlier #3159),
  i.e. the endpoint fields are **not** implemented upstream.
* What upstream DOES do today: it parses a wireguard endpoint and
  **silently ignores** the unknown AWG keys → the handshake leaves as
  plain WireGuard → a peer that requires the AWG header drop it →
  "registered WARP, nothing connects" exactly matches this signature.

AmneziaWG-3.1 obfuscation, for reference (amnezia-vpn/amneziawg-go):

| Field | Meaning |
|---|---|
| `Jc`, `Jmin`, `Jmax` | `Jc` junk packets of random length `Jmin..Jmax` sent before each handshake |
| `S1`, `S2` | junk bytes prepended to handshake init / response messages |
| `H1..H4` | remap of the four WireGuard message-type header values (the DPI fingerprint) |
| `I1..I5` (3.x) | special decoy/handshake messages (WireSock-style sugar; e.g. `ip=quic` disguises the whole session as QUIC) |

The **client and server must agree on all of these**; a plain-WG client
against an AWG peer is a hard fail, and vice versa an AWG client against a
plain-WG peer also fails (the junk packets break the header check).

## 2. Path A (recommended): `sing-box-lx` prebuilt AAR

**Fork:** <https://github.com/Leadaxe/sing-box-lx> (with the LxBox Android
app <https://github.com/Leadaxe/LxBox> proving the libbox path on real
devices).

* **Feature 003 — "AmneziaWG 2.0 / 3.x"**: wireguard endpoint fields
  `jc/jmin/jmax, s1–s4, h1–h4, i1–i5`, AWG 3.x `header_protection_key`,
  padding, trailers, ranged timings — "the full obfuscation set of
  amneziawg-go v3.1". Status: **"verified against live AWG 2.0 and 3.1
  servers"**.
* Everything sits behind build tags and each upstream release is merged
  within days; a build without the tags is upstream byte-for-byte.
  Tag set (single source of truth: `make -f Makefile.lx lx-print-tags`):
  `with_gvisor,with_quic,with_dhcp,with_wireguard,with_utls,with_clash_api,with_naive_outbound,with_purego,badlinkname,tfogo_checklinkname0,with_xhttp,with_awg,with_lx_comm`
* Bonus for this repo: feature 012 implements the **VLESS `encryption`
  (post-quantum `mlkem768x25519plus`) field** — the exact gap that today
  forces every PQ node through the :xray upstream — plus native XHTTP
  (feature 002). One AAR swap upgrades three weak spots at once.
* **Releases ship a prebuilt `libbox.aar`** (gomobile build of
  `experimental/libbox`, `with_xhttp + with_awg` baked in, SDK 21+).

### Integration steps

1. Download the latest `libbox.aar` from
   <https://github.com/Leadaxe/sing-box-lx/releases> (check `Libbox.version`
   after swap — the README documents it).
2. Replace `android/app/libs/libbox.aar` with it.
3. No Gradle/Kotlin/Dart change is required for AWG itself: the Kotlin side
   (`LibboxEngine.kt`) feeds the config JSON through
   `CommandServer.startOrReloadService` as before, and the Dart side
   (`OutboundBuilders.singBoxWireguardEndpoint`) already emits
   `jc/jmin/jmax/s1/s2/h1..h4` on the endpoint when the account carries
   AWG params.
4. For AWG-3.x extras (`i1..i5`, `header_protection_key`) add the fields to
   `AmneziaParams` (lib/domain/entities/proxy_profile.dart) and extend the
   endpoint builder — they pass through as unknown-forward params today and
   are preserved, so old persisted accounts survive.
5. Sanity gates after the swap:
   * `flutter analyze` + full test suite (config-generator tests must stay
     green — the emitted JSON shape does not change).
   * Device E2E: register WARP → enter AWG params → connect with
     `WARP first` → the singbox.log on device must show the wireguard
     endpoint dialing; `cloudflare.com/cdn-cgi/trace` through the tunnel
     must answer.
   * Regression: connect a plain (non-AWG) node — the stock paths must be
     untouched (tags are additive).

**Risk:** third-party fork; pin an exact release tag, diff the AAR against
upstream tags when upgrading, and keep the previous AAR in the repo history
as the rollback. License is GPL (upstream sing-box) — compatible with
bundling as long as the fork source link is kept (THIRD_PARTY_LICENSES).

## 3. Path B: Amnezia's own fork (`amnezia-box`)

**Fork:** <https://github.com/amnezia-vpn/amnezia-box> ("Amnezia's sing-box
fork with the AWG endpoint"; stable branch `master`, dev `dev`; **the Go
module path stays `github.com/sagernet/sing-box`**, so our generator needs
no changes).

* Pro: vendor-authored (Amnezia itself), most likely to track amneziawg-go
  releases (3.1) fastest.
* Con: **no prebuilt AAR** advertised on the README; build it yourself
  (below), and its feature set beyond AWG (VLESS encryption/XHTTP parity)
  is undocumented — validate per feature.
* Build follows the SAME recipe this repo already used for the stock AAR
  (docs/android/v0.4.1-routing.md) — clone this fork instead of SagerNet:

```
git clone --recurse-submodules --branch master \
  https://github.com/amnezia-vpn/amnezia-box
cd amnezia-box
go get golang.org/x/mobile/cmd/gobind && go install golang.org/x/mobile/cmd/gobind
gomobile bind -v -o libbox.aar -target android/arm64 -androidapi 24 \
  -javapkg=io.nekohasekai -trimpath \
  -ldflags "-X github.com/sagernet/sing-box/constant.Version=$(git describe --tags) \
    -X runtime.godebugDefault=multipathtcp=0,tlssha1=1 -checklinkname=0 -s -w -buildid=" \
  -tags "with_gvisor,with_quic,with_wireguard,with_utls,with_naive_outbound,with_clash_api,badlinkname,tfogo_checklinkname0" \
  ./experimental/libbox
cp libbox.aar <repo>/android/app/libs/libbox.aar
```

(Uses upstream `gomobile`, not the SagerNet fork — same notes as the
v0.4.1 doc: no `-libname`/`-buildvcs` flags, JDK ≥ 17 on PATH.)

Environment notes from the v1.14.0 build already performed here: Go 1.26.x,
NDK r27+, ~25 MB AAR output; expect ~10–20 min full build on Windows.

## 4. Rejected alternatives (documented so nobody re-investigates)

| Option | Why no |
|---|---|
| Upstream sing-box AWG | Open request #4045, not implemented in v1.14.x — nothing to build. |
| Separate `amneziawg-go` daemon app-side | Android ≥ 10 cannot exec() bundled binaries (W^X); the existing single-core guarantee (no external daemons on-device) exists precisely for this. Only the desktop runtimes can use the daemon. |
| Userspace AWG re-implementation in Dart/Kotlin | A whole crypto protocol (Noise *IK* + custom header obfuscation) — months of work, zero audit; a binary swap does it in an afternoon. |
| WireSock closed-source client | No libbox surface, no license for redistribution. |

## 5. Status of what is ALREADY done in the app (no fork needed)

* Config surface: `OutboundBuilders.singBoxWireguardEndpoint` emits
  `jc/jmin/jmax/s1/s2/h1..h4` when the WARP account carries AWG params
  (v0.4.8) — byte-correct for both forks above.
* Account storage: AWG params persist on the WARP account
  (`WarpRepository.saveWithAwgParams`), manual entry sheet on the WARP card
  (warp-generator.vercel.app paste-in).
* Chain directions: `WARP first` (app → WARP → node → internet) and
  `WARP last` (app → node → WARP → internet) build real detours in the
  front config.
* Desktop: the AWG runtime (`AmneziaWgRuntime`, amneziawg-go daemon) is the
  full-featured path today; only the Android tunnel engine is capped.

**So the Android gap is exactly one artifact: the AAR.** Swap it (Path A),
flip the WARP card to `WARP first` with AWG params set, and the masked hop
goes live.

---

## 6. Verification checklist after the AAR swap

1. `Libbox.version` logged at start == fork release.
2. Config with AWG params is ACCEPTED (engine log: endpoint created, no
   "unknown field" — upstream would silently strip them instead).
3. `WARP first` connect on an AWG-masked WARP peer: TUN up, probe through
   tunnel OK (`gstatic generate_204`), `trace` shows `warp=on/plus`.
4. AWG-off regression: plain WARP + plain nodes unaffected.
5. `grep -a "junk" lib/arm64-v8a/libgojni.so` inside the NEW AAR hits —
   a cheap CI-able proof that AWG code is in the binary.
