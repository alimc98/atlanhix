## Core execution path (§12/§13)

Verified by unit + E2E tests:

* VLESS+XHTTP → **Xray** (detector, ≥0.9 confidence) → Xray runtime launches →
  sing-box selector carries a SOCKS stub, **never a native outbound**
  (`engines_test.dart`, W2/W6 pairing tested).
* Native-capable profiles → sing-box outbound; WireGuard → sing-box endpoint;
  AmneziaWG → standalone daemon (never in the front selector).
* Unknown-core profiles execute as native sing-box outbounds unless they carry
  an Xray-only transport (defensive pairing).
* Hot-switch never swaps to a stub whose upstream daemon is not serving
  (SOCKS-greeting / inbound health gates).

Correctness > stability > security > performance — no benchmark was chased
at the expense of the verification steps above.

## Known limitations (explicit)

1. **AmneziaWG** requires a user-provided `amneziawg-go` binary; without it
   the runtime reports NOT INSTALLED (never pretends).
2. **MasterDNSVPN live E2E** needs a real DNS-tunnel server + the
   `mdvpn-client` binary (`ATLANHIX_MDVPN_E2E=1`); not available here.
3. **WARP live chain E2E** (`ATLANHIX_WARP_E2E=1`) requires internet egress
   to the Cloudflare registration API and a WG handshake; not verified here.
4. **Android** needs the Android SDK + the libbox artifact + a device; the
   architecture and Dart-side state machine are done and unit-tested, the
   on-device checklist in `docs/ANDROID_VPN.md` is outstanding.
5. Smart Connect uses sequential engine-start attempts after the parallel
   pre-probe; fully parallel engine starts are deliberately not implemented
   (port allocation + verification isolation).
6. Traffic statistics come from the sing-box Clash API (real counters).
   Engines that expose no counters report `null` — no synthesized numbers.
7. Windows system-proxy mode relies on per-user proxy settings; desktop TUN
   mode is planned for a later milestone (Android TUN is implemented).
